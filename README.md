# Deekseep Local API

An independent, open reimplementation of the **Local API** feature that the
Deekseep LSPosed module ships only in its Closed edition.

Deekseep is an LSPosed/Xposed module for the official DeepSeek Android app. Its
public source tree deliberately excludes the Local API: the upstream
`docs/FEATURES.md` states that "the Local API and its public-tunnel/keepalive
implementation are not part of this repository or source build", and
`BuildInfo.LOCAL_API_INCLUDED` is hard-coded to `false`.

This project restores that capability as ordinary, auditable source.

## What the Local API does

It runs a loopback HTTP server **inside the DeepSeek app process** and exposes
the app's native chat transport over two industry-standard protocols:

| Protocol | Endpoints |
| --- | --- |
| OpenAI Chat Completions | `GET /v1/models`, `POST /v1/chat/completions` |
| OpenAI Responses | `POST /v1/responses` |
| Anthropic Messages | `POST /v1/messages`, `POST /v1/messages/count_tokens` |

Both streaming (SSE) and non-streaming JSON are supported. Reasoning/thinking
deltas are surfaced as OpenAI `reasoning_content` and Anthropic `thinking`
blocks, so clients such as Codex, Claude Code and any OpenAI-compatible tool can
talk to DeepSeek through the app's own session.

## How it fits into the module

The upstream module already contains the whole feature except the server itself.
The relevant seam is:

- `z2` — the protocol/contract types shared between the module DEX and the
  gateway. `z2.Backend` is the callback the gateway uses to run a completion;
  the module already implements it (`Main.startz1` → `executeLocalApiCompletion`).
- `z13` — a reflective facade. It looks up `com.dsmod.probe.z1` by name and
  invokes `start`, `stop`, `endpoint`, `port`, `apiKey`, `setProtocolMode`,
  `rotateKey`, and friends.
- `z14` — the payload resolver. In the Closed edition this decrypts and loads a
  secondary payload DEX that contains `z1`. In the open source it is a stub that
  returns `null`.

In the shipped Closed APKs, `z2`/`z13`/`z15`/`z16` are present but **`z1` is
absent from `classes.dex`** — it lives only inside the encrypted payload. That is
the piece this repository provides:

- `src/com/dsmod/probe/z1.java` — the HTTP server and protocol conversion.
- `src/com/dsmod/probe/z14.java` — a drop-in payload resolver that resolves the
  gateway from the module class loader (and still prefers a decrypted payload
  file if the user supplies one).

`z2.java` and `z4.java` are copied verbatim from the upstream GPL-3.0 source so
that the gateway compiles against the exact contract the module expects.

## Building it into the module

Copy `src/com/dsmod/probe/z1.java` and `src/com/dsmod/probe/z14.java` over the
upstream `module/src/com/dsmod/probe/` directory, then build with
`LOCAL_API_INCLUDED = true`.

Three small gates must be opened in the upstream sources:

1. `BuildInfo.LOCAL_API_INCLUDED = true` (generated by the build script).
2. `Main.startz1` re-enrolls with a license server before starting the gateway.
   Guard that block with `BuildInfo.PROTECTED_BUILD` so an open build does not
   depend on a license server.
3. The two Local API menu entries in `DeekseepUi` are behind
   `BuildInfo.PROTECTED_BUILD && BuildInfo.LOCAL_API_INCLUDED`. Drop the
   `PROTECTED_BUILD` conjunct to show them.

A complete, reproducible build script that performs all of the above lives in the
sibling workspace (`work/build-local-api.sh`).

## Configuration

Settings are persisted to the `dq0_local_api` SharedPreferences file, which is
the same store the module UI uses, so the UI and server never disagree.

| Key | Meaning |
| --- | --- |
| `protocol` | `openai` or `anthropic` |
| `preferred_port` | Listener port (falls back to an ephemeral port if busy) |
| `api_key` | Bearer token / `x-api-key`; auto-generated on first start |

## Security notes

- The listener binds `0.0.0.0` so LAN clients can reach it; the API key is the
  only access control. Rotate it if you expose the port beyond loopback.
- Requests are relayed through the app's authenticated session, so anything that
  can reach the port can consume that account. Treat the key like a password.
- Request bodies are capped at 32 MiB and sockets time out after 10 minutes.
